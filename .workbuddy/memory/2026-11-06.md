## 日程页 0/0 圆环黑框 bug（已修复，工作区未提交）

根因：`SchedulePage.tsx` 的进度圆环类名 `ring` 与 **Tailwind v4 的 `ring` 工具类撞名**（devDeps 有 `@tailwindcss/vite`，扫描源码时把 `"ring"` 字符串当候选生成了工具类）。Tailwind 的 `.ring` = `box-shadow: 0 0 0 1px currentcolor`，`.ring` 元素无圆角 → 文字色的 1px 直角方框包住 0/0 计数器。用 playwright 探针抓到 `.ring` computed boxShadow 确认；dist CSS 里也搜到了生成的 `.ring{...}` 工具类。

修复：类名改 `todo-ring`——`SchedulePage.tsx` 238 行 + `index.css` 291-299（并加注释说明撞名历史）。复验：computed boxShadow = none，截图无方框。

排查手法（可复用）：本地 node 直跑 `node_modules/vite/bin/vite.js` 起服务（npm shim 被沙箱拦），playwright `channel:'msedge'` 免下载 Chromium，探针脚本 dump 目标元素及其祖先的 computed style。

顺带检查过其他撞名候选（border/underline/line-through/outline/blur/p-1）——均未作为类名使用，只有 ring 一处。agent-browser 的 bash shim 在沙箱缺 coreutils（dirname/sed/uname 全挂），不可用。

## 键盘遮挡抽屉输入框的根因与修法（手机 405f362，未推）

- 现象：所有底部抽屉里的输入框都被软键盘遮住（真机 Android 15）。
- **根因是两层假设同时失效**：① `targetSdk 35` = Android 15 起强制 edge-to-edge，Activity 不再因 `adjustResize` 缩窗，键盘浮在内容之上，`100dvh` 与 `documentElement.clientHeight` 都不变；② 旧实现反而假设「窗口已缩到键盘上方」，focus 时把抽屉 `bottom` 写成负值让它**下沉**贴住键盘上沿——窗口没缩，下沉等于把整块抽屉推进键盘底下。
- 修法（在 CSS 层重建 adjustResize）：store 用 `visualViewport` 量 `clientHeight - vv.height - vv.offsetTop` 写进 `--kb-real`（rAF 节流，`resize`+`scroll` 都跟）；`.app` 高度改 `calc(100dvh - var(--kb-real, 0px))`，贴底元素随壳整体上移。
- 三个关键坑：**基准必须取 `clientHeight` 而非 `innerHeight`**（部分 WebView 的 innerHeight 已扣键盘，差值恒 0 → 适配静默失效）；`.sheet` 的 `max-height` 必须从 `86dvh` 改 `86%`（dvh 锚视口，壳变矮它不变，抽屉会顶出壳外）；`AndroidManifest` 要显式 `windowSoftInputMode="adjustResize"`（否则可能退化到 adjustPan 整页平移）。
- 桌面「模拟输入法」改为与真机同一套高度通道（不再单独隐藏浮坞），模拟才有意义。
- 验证：tsc 0 error；冒烟 58 项 ALL PASS（新增 `--kb-real` 驱动壳收缩、聚焦输入框后抽屉不再下沉）；55dvh 键盘模拟下新建笔记抽屉 65→464 贴壳底，标题框/正文框全在壳内。

### 更正：visualViewport 方案在 WebView 里无效，键盘高度只能走原生（手机 d9f70d6，未推）

- 真机截图打脸：装包后界面**一动不动**，输入栏仍被键盘完整盖住——`--kb-real` 恒为 0。
- ★★ **WebView 里三条 Web 路径全都拿不到键盘高度**，这是本次最值钱的结论：
  ① `interactive-widget=resizes-content` 是 Blink 特性、**未接入 WebView**（index.html 里那条 meta 一直是 no-op）；
  ② `visualViewport.height` 在 Android WebView 里**要 Chrome 139+ 才响应 IME**，低于该版本毫无信号；
  ③ `CapacitorWebView.edgeToEdgeHandler()`（7.4.4）自己注册了 insets 监听，只取 `systemBars|displayCutout`，然后 **`return CONSUMED`** —— IME inset 在原生层就被吞了。默认配置（`adjustMarginsForEdgeToEdge: auto` + SDK 35）就会走到这条分支。
- 正解：`MainActivity` 用 `ViewCompat.getRootWindowInsets()` **主动读** `Type.ime().bottom`（不 setOnApplyWindowInsetsListener，否则顶掉 Capacitor 的处理器、状态栏 margins 坏掉），÷density 换算 CSS px 注入 `--kb-native`。

- Manifest 改 `adjustNothing`：`adjustResize` 在 Android 15 是 no-op、在老 Android 真缩窗，与本机制叠加会**双重扣**。
- CSS 改 `calc(100dvh - max(var(--kb-native,0px), var(--kb-real,0px)))`：两通道取大者，不相加。
- 顺带踩坑：**XML 注释不能含连续两个减号**，写 `--kb-native` 会让 `processDebugMainManifest` 直接 FAILED 且不指向注释。
