## 1. 现状（手机侧今天的行为，v1.6）

- 同步触发：**启动时 + 本地写操作后 + 手动「立即同步」**——没有「桌面变了」的感知通道。
- 引擎 `src/lib/sync.ts`：`since/cursor` 三域（ledger/schedule/notes）、LWW 合并、墓碑应用，v1.6 已全落地（`scripts/verify-sync.mjs` 78 项全过）。
- 已知实测结论（桌面侧探查，2026-11-08）：桌面「改动检测 → 下行变更集」链路完好；缺的只是手机拉取时机。**手机侧不用改任何合并/存储逻辑，只改「什么时候发起 pull」。**

## 2. 目标形态（一句话）

配对 + 在线 + App 前台时，手机与桌面之间**常挂一个 pull**：桌面任何同步域一动（含另一台手机的 push、桌面编辑器 / AI 工具 / 直接改文件），挂起的请求 <1 秒内返回，手机立即应用；没有动静就挂满超时再挂下一发——体感是「两台设备连着就是一份实时数据」。

## 3. 协议增量（桌面侧方案 §2 的手机侧视角）

- pull 请求体加可选 `wait`（毫秒）：`{ since: {...}, wait: 25000 }`。
- 响应加可选 `waitSupported: true`：本请求确实被挂起处理过（含超时空返回）。
- **`waitSupported` 是探测位**：旧桌面不认识 `wait`，立即返回且没有该字段 → 手机退回定时轮询。

## 4. 手机侧要改的清单（验收口径）

### 4.1 引擎 `src/lib/sync.ts`：挂起 pull 循环

1. 前台 + 已配对 + 探测到电脑在线 → 启动**挂起循环**：
   ```
   while (前台 && 配对 && 在线):
     resp = pull(since=本地游标, wait=25000, signal=当前循环的 AbortController)
     应用 changes / tombstones（现有 applyRemote 逻辑零改动）
     更新游标
     if resp.waitSupported: 立即发下一发
     else: 进入轮询模式（30s 间隔），并记「对端不支持」避免反复探测
   ```
2. 循环退出 / 重建时机：退后台、取消配对、桌面 ping 连续失败。重建时**先取消在途请求**（AbortController），再走一次立即对账（不带 wait）把积压拉平。
3. 指数退避：挂起请求失败（网络断 / 桌面重启）→ 1s / 2s / 5s / 10s / 30s 封顶重试；成功后回到挂起循环。
4. **探测与降级**（兼容矩阵，桌面方案 §2.4）：首个 `wait` 请求若无 `waitSupported` → 30s 定时轮询 + 状态标「旧桌面」；后续不必反复探测（可选：每次进前台重探一次，桌面升级后自动升级为实时）。

### 4.2 与既有触发的关系

- **本地写操作后**：照旧立即 push + 立即对账——先取消在途挂起请求（AbortController），push 完成后重建挂起循环。不要让挂起请求和 push 后的对账并发跑两份 pull。
- **手动「立即同步」**：同上，顶掉挂起、立即拉平、重建循环。
- 手机自己的 push 到达桌面后，桌面会 `pokeSync()` 唤醒**其他设备**的挂起请求（桌面方案 §3.2）；本机 push 后走的是上面的主动对账，不依赖唤醒。

### 4.3 前后台（电池，硬要求）

- 退后台（webview `visibilitychange` / Capacitor `appStateChange`）：暂停挂起循环（取消在途请求）。
- 回前台：立即对账一次（不带 wait）→ 重建挂起循环。
- 依据：挂起 fetch 在后台被系统冻结时行为不可控，宁可显式停，回前台拉平即可。

### 4.4 契约脚本

本仓 `scripts/verify-sync.mjs` 补 v1.7 断言（对齐桌面侧 `.AGENT/scripts/phone-companion/verify-companion-protocol.mjs` §8 的镜像语义）：

1. 引擎收到 `waitSupported: true` → 维持挂起循环（不发定时轮询）。
2. 收到无 `waitSupported` 的响应 → 切入 30s 轮询并标「旧桌面」。
3. 在途请求被 AbortController 取消后，push-后对账与循环重建不并发重复 pull。
4. 退避序列 1/2/5/10/30 封顶（纯函数直测）。
5. 兼容矩阵口径与桌面契约逐条对齐（两仓脚本都要过是仓规）。

### 4.5 UI

- 同步状态文案：「实时」（挂起中）/「轮询 30s（电脑版本较旧）」/「离线待同步」。位置沿用现有同步徽标区，不新开面板。

## 5. 端到端验收（与桌面方案 §7-P3 合并跑）

- [ ] 桌面改 `移动端/<设备名>/` 内文件 → 手机 <1s 出现新内容（前台）。
- [ ] 手机改笔记 → push → 另一台挂起设备 <1s 收到（单设备场景即：桌面伴侣面板状态即时变化）。
- [ ] 手机退后台 → 挂起请求取消；回前台 → 自动对账 + 恢复实时。
- [ ] 桌面杀掉重开 → 手机退避重连 → 自动恢复实时（无人工干预）。
- [ ] 对旧桌面引擎（v1.6 APK）→ 轮询模式，行为与今天一致。
- [ ] 飞行模式开关 10 次 → 无重复条目、无幽灵游标（退避与取消语义正确）。

## 6. 明确不做（本拍边界）

- WebSocket / SSE（长轮询已 <1s，不值新端点）；
- 分域唤醒的精细信号（粗粒度 poke 足够，空 pull 开销可忽略）；
- 后台常驻同步（后台静默，回前台拉平；iOS/Android 后台网络限制不值得对抗）；
- 桌面 → 手机反向直连（协议模型不变，手机仍无服务端）。
